# CIRCUIT FORGE v4 — Laboratory methods

Date: 2026-09-05. Software research prototype; no physical hardware or flight data was used. No model was trained on the user's earlier NPZ package. New fault data was generated by the independent single-topology engine in this repository.

## Finite op-amp model

Topology: R1 input–a, R2 a–b, C1 a–output, C2 b–ground. The op-amp is a unity-gain buffer following node b, with infinite input impedance and zero output impedance. Open-loop response: `A(s)=A0/(1+s*A0/(2π*GBW))`. GBW is the gain-bandwidth parameter of the single-pole open-loop model.

Define `a=C2(R1+R2)`, `b=R1R2C1C2`, `k=R1C1`, `u=1/A0`, and `t=1/(2π*GBW)`:

`H(s)=1/[d0+d1*s+d2*s²+d3*s³]`

- `d0=1+u`
- `d1=(1+u)*a+t+u*k`
- `d2=(1+u)*b+t*(a+k)`
- `d3=t*b`

The maximum absolute dB deviation is calculated in the passband, and the minimum attenuation in the stopband. The derivative of the squared-magnitude denominator with respect to `x=ω²` is quadratic; all positive roots are checked. Narrow resonances therefore do not depend solely on the plot sampling interval for detection.

`tests/lab.test.ts` compares against an independent three-node complex KCL solution at 800 points. `scripts/validate-ngspice.ts` runs native ngspice 47 on 30 circuits at 401 frequencies each. The maximum relative complex difference across 12,030 points was 2.16×10⁻¹⁴; see `ngspice-validation.json`. This validates the implementation of the same linear model. Saturation, slew rate, noise, ESR, finite output impedance, supply effects, and temperature effects are not included.

Default A0=100 dB and GBW=10 MHz match the parameters in the Claude work log. The current Claude source archive has not been received, so integration of its 13-topology engine is not claimed. `/filter` retains the ideal engine; `/lab` uses the finite engine.

## Adaptive-budget AI

Every condition starts with eight shared, distinct E24 circuits. Search uses log space over R 1–100 kΩ and C 1–100 nF. Tolerances are independent uniform R/C deviations. A full evaluation uses 48 shared training draws; the score is the nearest-rank 95th percentile of the maximum normalized band violation. Lower is better.

The new method screens candidates using the first eight of those 48 draws. A GP augments the four log-R/C coordinates with `tanh(screening score)` and learns to predict `asinh(full score)`. A candidate is promoted to detailed analysis if expected improvement exceeds 0.006 or the pending pool reaches 24. Eight cached results are reused; only 40 new draws are computed. Partially screened candidates cannot win. This is experiment-budget allocation using a learned surrogate, not reinforcement learning.

Baselines are the existing four-dimensional GP/EI search and log-uniform random search. All three share initial candidates, tolerances, and a budget of 768/1536/3072 AC circuit realizations. One realization calculates all band metrics for one circuit; equal realization counts do not imply equal CPU time. Wall-clock time is recorded separately. Frozen winners receive 1,024 independent draws per method, outside the search budget: 3,072 final test evaluations in total.

Thirty experiments used predeclared seeds 0–9, three frequency conditions, a budget of 1,536, and A0=100 dB / GBW=1 MHz. `budget-benchmark.json` preserves all candidate histories:

| Passband / stopband | Adaptive-budget AI | Standard GP | Random |
|---|---:|---:|---:|
| 100 / 500 Hz | 10.0% | 0.0% | 0.0% |
| 1,000 / 5,000 Hz | 27.5% | 39.3% | 23.2% |
| 10,000 / 50,000 Hz | 39.7% | 50.5% | 39.1% |

Values are mean independent tolerance yield across 10 seeds. They do not establish general superiority. Methods tuned after this report should be evaluated on new held-out targets and seeds. A future experiment could measure the value of screening information against GP overhead under equal wall-clock budgets and through ablations.

## Trained fault model

Six classes: healthy, C1 drift, C2 drift, C1 open, R1 open, and R2 short. Drift multipliers are 0.35–0.70 or 1.40–2.00. C1 open is represented by 1 fF residual capacitance, R1 open by 1 GΩ, and R2 short by 0.1 Ω. Only one fault occurs at a time.

The nominal circuit and op-amp parameters are known. Features are magnitude/phase response differences from the nominal response at 12 frequencies relative to the input: 24 inputs → 32 tanh units → six softmax outputs. Frequencies are fixed multiples of nominal f0. The fault label is not a model input.

- 800 distinct training circuits, 9,600 measurements.
- 200 distinct validation circuits, 1,200 measurements.
- 200 distinct test circuits, 1,200 measurements.
- Circuit R/C groups are disjoint across all three sets.
- Uniform R ±1%, C ±5%; Gaussian measurement noise with standard deviations of 0.15 dB magnitude and 1° phase.
- Training domain: R 1–100 kΩ; C 1–100 nF; A0 80–120 dB; GBW 100 kHz–100 MHz.
- Standardization uses the training set only. NumPy/Adam training runs for 250 epochs; the checkpoint with the lowest validation cross-entropy, epoch 235, was selected. The test set was then evaluated once.
- A predeclared softmax-score threshold of 0.60 marks low-confidence results uncertain. Scores are not calibrated probabilities.

Results: 98% top-1 accuracy, 97.5% when uncertain results count as incorrect, and 14 uncertain predictions. There were 0 false alarms among 200 healthy measurements and 2 missed faults among 1,000 faulty measurements. Zero observed false alarms do not guarantee zero future errors. Generalization to multiple faults, different noise, unknown inputs, other topologies, and real hardware was not validated.

`generate-fault-data.ts` and `train-fault-model.py` reproduce the process. The training script writes data/group hashes, model SHA-256, and an independent NumPy prediction fixture to `fault-model-report.json`. The browser verifies the model hash; TypeScript predictions are tested against the NumPy fixture within 10⁻¹². Raw data is not sent from the user's device.

## Wokwi and non-Arduino boards

Five board mappings: UNO R3, classic Nano, Mega 2560, ESP32-DevKitC V4 (WROOM-32E), and original Raspberry Pi Pico (RP2040). The latter two use their own pin profiles: ESP32 ADC1/GPIO names and Pico GP names with I²C0 on GP4/5. Incompatible mappings, such as a direct 5 V sonar connection, are blocked.

Ten module types: LED, potentiometer, button, common-cathode RGB LED, passive buzzer, DHT22, DS18B20, MPU6050, SSD1306, and HC-SR04. Code, `diagram.json`, `libraries.txt`, physical wiring notes, and a manifest are exported as a ZIP. LEDs receive 1 kΩ series resistors and single-wire sensors receive 4.7 kΩ pull-ups. Wokwi's OLED has four pins; the physical Adafruit RESET pin becomes -1 in simulation, while the normal physical-board sketch retains its RESET assignment.

Files are not uploaded to Wokwi automatically. CLI diagram validation and Arduino CLI compilation do not replace Wokwi cloud execution or hardware tests. Wokwi CLI 0.26.1 reports an informational “undocumented type” message for DS18B20 and ESP32-DevKitC V4; the official DS18B20 part documentation and ESP32 board.json pin names were checked separately. Outputs and core versions are in `embedded-validation.json`.

## Virtual sensor signal

A second vibration sinusoid is added to a useful 12 Hz, 0.6 g signal. The finite engine calculates the steady-state response to both sinusoids, which is then sampled. RMS error is calculated against the clean signal without time alignment, so it includes both delay and amplitude distortion. This is not real flight/IMU data, a transient simulation, or ADC quantization.
